==========================
Django 6.1.3 release notes
==========================

*November 3, 2026*

Django 6.1.3 fixes five security issues with severity "low", one security issue
with severity "moderate", and several bugs in 6.1.2. It also adds compatibility
with Python 3.15.

Bugfixes
========

* Fixed a regression in Django 6.1 where the YAML serializer crashed if passed
  the ``sort_keys`` option (:ticket:`37405`).

* Fixed a regression in Django 6.1 where a :class:`~django.db.models.Value`
  expression with a ``None`` value and an output field other than
  :class:`~django.db.models.JSONField` crashed on SQLite when used in a
  top-level :class:`~django.db.models.JSONField` :lookup:`in` lookup
  (:ticket:`37403`). Using such an expression in an ``IN`` lookup is likely
  unintended, since SQL ``NULL`` cannot match any value.

* Fixed a regression in Django 6.1 where
  :meth:`~django.forms.BoundField.legend_tag` with a custom ``attrs`` could add
  the :attr:`~django.forms.Form.required_css_class` more than once
  (:ticket:`37463`).

* Added compatibility for ``oracledb`` 26.0.0+ (:ticket:`37411`).

* Fixed a crash in :djadmin:`makemessages` on Windows when processing files
  with non-ASCII names on Python 3.15+, or with :ref:`UTF-8 mode
  <python:utf8-mode>` enabled on older Python versions (:ticket:`37447`).

* Fixed a bug in Django 6.1 where accessing a deferred field with the
  :attr:`~django.db.models.FETCH_PEERS` fetch mode overwrote values that
  peer instances had already loaded from the database or modified locally,
  and raised ``KeyError`` when a peer's row had been deleted (:ticket:`37436`).
