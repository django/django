===========================
Django 5.2.19 release notes
===========================

*November 3, 2026*

Django 5.2.19 fixes four security issues with severity "low" and one security
issue with severity "moderate" in 5.2.18.

CVE-2026-108147: Potential memory exhaustion in ``MultiPartParser`` via base64-encoded file upload
==================================================================================================

When using ``django.http.multipartparser.MultiPartParser``, multipart uploads
with ``Content-Transfer-Encoding: base64`` could be buffered entirely in
memory, regardless of :setting:`FILE_UPLOAD_MAX_MEMORY_SIZE`, before being
passed to upload handlers, potentially consuming excessive memory.

This issue has severity "low" according to the :ref:`Django security policy
<severity-levels>`.

CVE-2026-111211: Potential log injection via unescaped geometry form values
===========================================================================

:class:`~django.contrib.gis.forms.GeometryField` and its widgets logged invalid
submitted values directly, allowing control characters (e.g. newlines or ANSI
escape sequences) to be written unescaped into logs. This could enable log
injection or forgery, letting attackers manipulate log appearance or
structure, especially in logs processed by external systems or viewed in
terminals.

This issue has severity "low" according to the :ref:`Django security policy
<severity-levels>`.

CVE-2026-111362: Server-side request forgery via ``crs`` member of GeoJSON geometries
=====================================================================================

Earlier versions of the :rfc:`GeoJSON spec <7946#section-4>` allowed specifying
a coordinate reference system (CRS) by URL. Since GDAL still resolves these
URLs, any validation, save, or query path where a geometry is instantiated from
user input allowed an attacker to submit a malicious CRS that would make a
network request as the Django process user, or read a file, or both.

:ref:`Lookups against spatial fields <spatial-lookups-intro>`, the
:class:`~django.contrib.gis.forms.GeometryField` form field, and
:class:`~django.contrib.gis.geos.GEOSGeometry` now reject GeoJSON geometries
with CRS references to external resources. The
:class:`~django.contrib.gis.gdal.DataSource` and
:class:`~django.contrib.gis.utils.LayerMapping` utilities for loading trusted
data continue to accept these values.

This issue has severity "moderate" according to the :ref:`Django security
policy <severity-levels>`.
